Introduction

Professional Self-Assessment

I came into the Computer Science program at Southern New Hampshire University after about ten years in B2B sales and a marketing degree from Arkansas State. I knew how to talk to customers, figure out what they actually needed, and explain a product in plain terms, but I did not know how to build one. This program changed that. Over the last several terms I have built a full stack web app, an Android app, a 3D graphics scene, a database-driven dashboard, and machine learning models. Putting together this ePortfolio in my capstone pulled all of that work into one place and made me look at my own code the way an employer or a teammate would. It also made my goals clearer. I want to work in backend, full-stack, or cloud and DevOps roles, and this portfolio is built to show the skills those jobs ask for.

Collaborating in a team environment is where my sales background helps the most. I have spent years working with account teams, managers, and clients who all wanted different things, and I learned how to keep everyone moving toward the same goal. In this program I carried that into how I work with code. I use Git and GitHub for version control, I write comments and documentation so someone else can follow my work, and in my capstone I did a full code review of my own artifacts, including code written by my instructor, before changing anything. Reviewing existing code carefully and explaining what I changed and why is a big part of working on a real development team.

Communicating with stakeholders is a skill I brought with me, and the program gave me technical things to communicate. In CS 465 I wrote a Software Design Document for a full stack travel app. In CS 370 I wrote a white paper on data privacy law and neural network personalization. In my capstone I recorded a code review video and wrote a narrative for each enhancement, explaining technical decisions to a reader who had not seen the code. I am comfortable translating between the technical side and the business side, which is something a lot of teams need.

For data structures and algorithms, my clearest example is my CS 340 animal shelter dashboard. The original code picked a rescue filter with a chain of if and elif statements and looked up map data by column number. I replaced the chain with a dictionary lookup table, which takes constant time and makes adding a new filter a one-line change, and switched the map to look up data by column name so it would not break if the data changed. In my CS 330 project I replaced about 250 lines of repeated drawing code with a struct and a single loop. Both changes taught me that choosing the right data structure is as much about making code easy to change as it is about speed.

In software engineering and databases, I have worked across the full stack. I built a MEAN stack app in CS 465, an Android app with a SQLite database in CS 360, and a Python dashboard backed by MongoDB in CS 340. For my capstone database enhancement, I added an index on the fields the dashboard searches most and added safeguards to the update and delete methods. In my software design enhancement, I found and fixed two real bugs in my CS 330 graphics project: a texture cleanup function that leaked GPU memory, and a search function that always reported success even when it found nothing.

Security is the area where this program changed my thinking the most. My original CS 340 dashboard had the database username and password typed right into the code, and the repository was public. In my capstone I moved those credentials into environment variables and blocked update and delete calls that would match every record in the database. I also learned that removing a password from the code does not remove it from the project's Git history, so the real fix in a production setting is to change the password. I now look at code by asking how it could be misused or break, not just whether it works.

The three artifacts in this ePortfolio show those skills working together. The first is my CS 330 OpenGL campfire scene, enhanced for software design and engineering. I fixed a memory leak and a broken search function, moved repeated input code into a helper method, and refactored the rendering code to use a struct and a loop. The second and third come from my CS 340 animal shelter dashboard. For algorithms and data structures, I replaced the filtering logic with a lookup table and made the map lookups safer. For databases, I secured the credentials, added an index, and protected against accidental mass updates and deletes. Together they show that I can step into an existing codebase, find what is wrong or fragile, and improve it in a way that is safe, maintainable, and clearly explained. Each artifact below includes the original code, the enhanced code, and a narrative explaining what I changed and why.
